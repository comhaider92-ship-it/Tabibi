# Phase V33 — Mobile schedule management

## Delivered
- Added a mobile schedule-management screen reachable from the doctor and facility-owner dashboards.
- Doctors can load and save their weekly working days and time windows, add one optional break per day in the UI (API supports up to four), create individual future availability slots, list their slots, and open/close individual slots.
- Facility owners can select one of their own facilities (including facilities not yet approved), choose a service, load and save that service's independent weekly schedule, generate availability for a date window of up to 31 days, and list/open/close service slots. Slot duration remains controlled by the service's configured `expectedDurationMinutes` on the backend.
- Doctors and facility owners can create temporary closures, review active closures, and restore a closure.
- Closure creation surfaces backend warnings about affected confirmed bookings; bookings are not silently cancelled.
- Added owner-scoped service/schedule/slot listing and slot-status routes. Closing or reopening a facility slot is rejected when a requested or confirmed booking is attached; reopening also rechecks active closures and weekly rules.
- All requests use authenticated role-protected backend routes. No backend schema or migration change was needed.

## Important behavior and limitations
- Weekly schedule editing currently exposes one break per day; backend validation supports up to four breaks.
- Doctor appointment duration is not imposed by the app. The doctor adds individual slots with explicit start/end times.
- Facility slots are generated by the backend using each service's configured duration.
- Date/time entry uses the Iraq UTC+03:00 offset and `Asia/Baghdad` timezone.
- UI was source-checked only. Dependencies are not installed in this working package; TypeScript build, Expo bundling, database integration tests, and physical Android testing have not been run.
