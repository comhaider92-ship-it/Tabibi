# طبيبي — V13: دوام الطبيب والمواعيد المتاحة

## القرارات المعتمدة
- لا توجد مدة كشف مفروضة ولا يتم توليد المواعيد آلياً من مدة ثابتة.
- الطبيب ينشئ كل موعد متاح بتوقيت بداية ونهاية يحددهما بنفسه.
- يمكن إنشاء فترات متعددة في اليوم الواحد مع ترك الاستراحات كفجوات زمنية لا تُنشأ خلالها مواعيد.
- لا يوجد جدول أسبوعي ثابت؛ الطبيب ينشئ المواعيد بحسب الأيام التي يختارها.
- يمكن فتح/إغلاق أو تعديل موعد منفرد، أو فتح/إغلاق مجموعة مواعيد.
- المريض يرى المواعيد المفتوحة المستقبلية فقط؛ المحجوز والمغلق والماضي لا يظهر.
- يجب أن يغلق الموعد عند نجاح الحجز وألا يقبل حجزاً مكرراً.

## API المضافة
- `POST /doctors/me/availability-slots` إنشاء مجموعة مواعيد.
- `PATCH /doctors/me/availability-slots/:id` تعديل موعد أو فتحه/إغلاقه.
- `PATCH /doctors/me/availability-slots/bulk/:status` فتح أو إغلاق مجموعة عبر ids.
- `GET /doctors/:doctorId/available-slots?from=&to=` عرض المتاح فقط.

## ملاحظة تكامل مهمة
هذه الحزمة تضيف طبقة المواعيد وقاعدة بياناتها واستعلام العرض. ربط الحجز الحالي بعملية ذرّية واحدة (قفل صف الموعد + إنشاء الحجز + إغلاق الموعد) ما زال مطلوباً قبل اعتبار منع السباق/الحجز المكرر مكتملاً في الإنتاج. لا تشغّل migration على قاعدة إنتاج قبل النسخ الاحتياطي والاختبار.
