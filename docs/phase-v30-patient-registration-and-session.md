# طبيبي V30 — تسجيل المريض والتحقق والجلسة الآمنة

## ما أضيف
- واجهة تسجيل مريض جديد بالاسم الكامل ورقم الهاتف أو البريد الإلكتروني وكلمة مرور لا تقل عن 10 أحرف.
- ربط إنشاء الحساب بطلب رمز تحقق OTP ثم شاشة إدخال الرمز وإعادة طلبه.
- جعل التسجيل العام في الخادم للمريض فقط؛ لا يمكن إرسال دور طبيب أو مالك عبر endpoint تسجيل المريض، والخادم يفرض `patient`.
- منع دخول حساب المريض قبل توثيقه. حسابات الطبيب والمالك الموجودة لا تتأثر بهذا الشرط.
- تخزين رمز الدخول في `expo-secure-store` بدلاً من الذاكرة فقط، واستعادة الجلسة والتحقق منها عند تشغيل التطبيق.
- إضافة تسجيل الخروج ومسح رمز الجلسة المخزن.
- منع حساب الطبيب أو المالك من استخدام واجهة تطبيق المريض.

## API المستخدم
- `POST /api/v1/auth/register`
- `POST /api/v1/auth/otp/request`
- `POST /api/v1/auth/otp/confirm`
- `POST /api/v1/auth/login`
- `GET /api/v1/auth/me`

## حالة إرسال OTP
الخدمة الحالية في `OtpDeliveryService` لا تتصل بمزوّد SMS أو بريد حقيقي. في بيئة التطوير تسجل الرمز في سجل الخادم فقط، وفي production ترفض الإرسال برسالة تفيد أن المزوّد غير مربوط. لذلك لا يمكن اعتبار التحقق عبر SMS/Email جاهزاً للإطلاق قبل إضافة بيانات مزود الإرسال وربطه واختباره فعلياً.

## تثبيت التطبيق
أضيفت `expo-secure-store` بالإصدار المتوافق مع Expo SDK 52 (`~14.0.1`) وأضيف plugin إلى `mobile/app.json`. بعد تثبيت اعتماديات mobile يلزم إعادة إنشاء/تشغيل تطبيق Expo كي تتوفر المكتبة الأصلية.

## التحقق
`python scripts_verify_v30.py` يتحقق من وجود وربط المزايا برمجياً. لا يعني ذلك نجاح TypeScript build أو اختبار التطبيق على جهاز.

## ما لم يُنجز بعد
- لا يوجد مزود SMS أو Email فعلي.
- لا يوجد بناء APK أو اختبار على جهاز Android.
- لم تُشغّل TypeScript compiler أو اختبارات تكامل قاعدة البيانات؛ اعتماديات المشروع غير مثبتة في بيئة التسليم.
- شاشة استعادة كلمة المرور لم تُضف في هذه المرحلة.
