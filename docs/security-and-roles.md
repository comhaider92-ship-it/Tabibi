# V10: الحسابات والصلاحيات

- patient: ينشئ حجزاً بصفته حاجزاً؛ `bookedByUserId` يُستخرج من JWT.
- doctor: لا يمكنه إنشاء حجز مريض عبر مسار المرضى؛ صلاحيات إدارة ملف الطبيب وجداوله قادمة.
- owner: لا يوجد تسجيل ذاتي للمالك؛ ينشأ حساب أولي من متغيرات البيئة.
- الوصول للحجز: المريض الحاجز أو المستفيد أو الطبيب المرتبط أو المالك يستطيع القراءة وفق الفحص الحالي.
- الإلغاء: الحاجز أو الطبيب المرتبط أو المالك.

## ملاحظات أمنية
- `isVerified` يبدأ false للحسابات الجديدة، لكن تدفق OTP لم يُنفذ بعد؛ يجب منع العمليات الحساسة حتى التوثيق في الإصدار التالي.
- لا يوجد rate limiting أو refresh token أو نسيت كلمة المرور بعد.
- يجب التحقق من أن doctorId يعود لحساب role=doctor وأن beneficiaryId يعود لمستخدم مسموح للمريض بالحجز عنه.
- يلزم إضافة اختبارات حقيقية للتزامن، والصلاحيات، والتسجيل، وتسجيل الدخول قبل الإنتاج.
